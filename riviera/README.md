# Riviera

A private-concierge planner for Mykonos, Ibiza and St. Tropez. Guests answer
four questions and Claude composes a day-by-day programme from a fixed
inventory of venues.

## Running it

```bash
npm install
cp .env.example .env.local     # then paste a real key into .env.local
npm run dev
```

Without a key the app runs and the form works; requesting a programme returns
"The concierge desk is not configured correctly."

## The one server-side piece

`api/itinerary.js` is the only code that is not a static asset. It holds the
Anthropic API key and calls the Messages API. It has no database and no
state — every request is self-contained.

It exists because a key shipped to the browser is a public key: anyone can
read it out of the bundle and spend against the account. `ANTHROPIC_API_KEY`
is deliberately **not** prefixed with `VITE_`, so Vite will refuse to inline
it into client code.

In development a small Vite plugin (`vite.config.js`) mounts the same module
at `/api/itinerary`, so `npm run dev` behaves like production. On Vercel the
file is picked up as a serverless function with no extra configuration; on
another host, run it behind any Node endpoint that speaks `(req, res)`.

## The desk view

`/admin` lists every request raised **in that browser**: reference, island,
dates, party size, the selected arrangements and the estimated volume, plus a
combined figure across all of them.

It is not a shared inbox. Requests are held in `localStorage`, so a request
made on a guest's phone never reaches the desk's laptop, and clearing site
data erases them. The page says this on itself. A real inbox needs somewhere
to post requests to.

Routing uses real paths, so any host must fall back to `index.html` for
unknown routes; `vercel.json` does that while leaving `/api` alone.

## Editing the inventory

`src/data/inventory.json` holds every bookable venue and service — 81
entries, 27 per island, across twelve categories (beach clubs, dining,
nightlife, VIP tables, yachts, watersports, cars, transfers, villas,
wellness, private chef, culture). The categories in `meta.categories` are
also the chips a guest picks from in the brief, so adding one there adds it
to the form. The
model may only use what is in that file — it is instructed to copy names and
`price_estimate` verbatim, and the client checks the returned plan against
the inventory and flags anything it does not recognise.

Prices are the desk's own estimates, not quotes. Update `meta.updated` when
you revise them; the date is shown to guests.

Named venues are real places. Service entries (jet ski hire, supercar hire,
private chef) are descriptions of what the desk arranges, not the names of
particular operators.

## Pictures

The app shows a photograph wherever the desk has one, and a generated plate
everywhere else. Nothing in the code changes when photography arrives — the
app reads `src/data/photos.json`, and if a set is missing, or a photo fails
to load in the browser, it falls back to the plate.

### Getting real photographs in

**Your own, or the venue's.** Drop files into `public/photos` named
`<island>-<category>[-n].<ext>`:

```
mykonos-beachclub-1.jpg   ibiza-yacht.jpg   st-tropez-restaurant-2.webp
```

Islands are `mykonos`, `ibiza`, `st-tropez`; categories are the twelve in
`inventory.json`. Where the licence needs attribution, add
`public/photos/credits.json` keyed by filename (`author`, `source`,
`sourceUrl`, `license`) — the app prints it under the picture. Then:

```bash
node scripts/index-photos.mjs
```

It reports what it indexed, what it ignored, and which sets are still on
plates.

**Or from a stock library.** Both providers issue a free key:

```bash
UNSPLASH_ACCESS_KEY=… node scripts/fetch-photos.mjs
PEXELS_API_KEY=…      node scripts/fetch-photos.mjs
node scripts/fetch-photos.mjs --dry-run     # prints the queries, downloads nothing
```

It downloads two landscape photographs per island and category, writes the
attribution, and tells you to run the indexer. The search terms live at the
top of that file and are the whole art direction — edit them.

These are **representative** photographs: a Mediterranean beach club, not
Nammos. That is why the app credits the photographer rather than captioning
the venue. For pictures of the venue itself, ask the venue.

### The plates

`public/images` holds one per entry, generated by
`node scripts/build-plates.mjs` from the entry's category and name: a duotone
ground in the category's tint with its motif. Deliberately abstract, so they
never pretend to be a photograph of anywhere.
